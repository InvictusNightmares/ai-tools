先在本 `policy-log/` 目录执行以下命令，将指定上游源码还原到独立的临时工作区并应用补丁：

```sh
set -e
POLICY_LOG_DIR="$(pwd)"
POLICY_BUILD_DIR="$(mktemp -d)"
curl --fail --location \
  'https://codeload.github.com/Wei-Shaw/sub2api/tar.gz/578785ee7fb35030b094b69624efe25670a36f5f' \
  --output "$POLICY_BUILD_DIR/upstream.tar.gz"
printf '%s  %s\n' \
  'd516caf91120b4483bd95cd385fef317514a08ecda4acd3e018560441f27082d' \
  "$POLICY_BUILD_DIR/upstream.tar.gz" | shasum -a 256 -c -
tar -xzf "$POLICY_BUILD_DIR/upstream.tar.gz" -C "$POLICY_BUILD_DIR"
cd "$POLICY_BUILD_DIR/sub2api-578785ee7fb35030b094b69624efe25670a36f5f"
git apply --check "$POLICY_LOG_DIR/policy-log.patch"
git apply "$POLICY_LOG_DIR/policy-log.patch"
```

下载、校验或补丁应用任一步失败时先停止，不继续构建。后续源码改动需同时更新 `source/`、补丁及 `upstream.json` 中的补丁校验值。

依赖版本以还原项目中的 `backend/go.mod`、`frontend/package.json`、`frontend/pnpm-lock.yaml` 和 `Dockerfile` 为准。该基线后端要求 Go 1.27.0；构建工作区使用 Go 1.27.1。Docker 构建使用 Node 24、pnpm 9，并将前端产物嵌入 Go 程序。

在上一步还原的完整项目根目录构建 Linux amd64 镜像：

```sh
docker build --platform linux/amd64 \
  --build-arg VERSION=0.2.1+policy-log.7 \
  --build-arg COMMIT=578785ee-policy-log7 \
  -t sub2api-local:0.2.1-policy-log7 .
```

该命令只构建镜像。应用部署另行执行，不能用官方镜像替代构建出的定制镜像。

使用本机工具链时，先构建前端，再编译带 `embed` 标签的后端；单独运行后端默认构建命令不会保证嵌入已更新的页面。

```sh
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend run build
cd backend
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build \
  -tags embed -trimpath \
  -ldflags='-s -w -X main.Version=0.2.1+policy-log.7 -X main.Commit=578785ee-policy-log7 -X main.BuildType=release' \
  -o bin/sub2api-policy-log7 ./cmd/server
```

## 保留定制功能的升级流程

左上角仍使用“更新 → 重启”。`policy-log.6` 的后台入口只接受定制发布目录中的程序，更新检查、安装和历史版本回退均不会下载官方整包。发布目录缺失、包不完整或 SHA256 不一致时停止更新，当前程序保持运行。更新响应丢失或刷新页面后，后台仍会显示“重启”完成待生效更新。

[upgrade/build.py](upgrade/build.py) 在 GPU 服务器的 CPU 上执行：

1. 每小时读取官方 `/releases/latest` 的稳定发布；REST API 限流时，只回退到官方网页 `/releases/latest` 的同源稳定版本跳转。Atom 订阅源也可能包含仅创建 tag、尚未正式发布的版本，不能用来选择升级目标。首次构建通过官方 commit API 解析精确提交，API 不可用时使用 `git ls-remote`（含 annotated tag 解引用）；固定基线归档和功能补丁均校验 SHA256。
2. 在临时目录按“原基线、定制文件、新版官方文件”做三方合并，冲突、新增文件碰撞或官方删除接入文件时停止。
3. 若数据库迁移文件或迁移执行器相对基线有变化，停止自动发布，先完成兼容性验证并更新基线。不能在未知迁移兼容性的情况下承诺二进制回退。
4. 使用固定镜像摘要的 Node 24、Go 1.27.1 隔离容器，限制 8 个 CPU、12 GiB 内存，不使用 GPU。执行正文记录、HTTP/SSE/WebSocket 关联、管理员边界、升级完整性、待重启恢复测试以及前后端生产构建。隔离容器另以 UID 1000、只读发布挂载及与生产相同的持久程序路径，实际执行自替换、备份、待重启恢复和重复点击验证。
5. 将验证通过的程序经现有 SSH 传到美西；东京通过现有 SSH 接收控制信息，再从美西主动下载加密更新包。每端先校验程序，再原子更新发布目录；一端离线不阻止构建和另一端接收。没有新程序时，两端只接收小体积目录信息。
6. 在无外部网络、无生产数据的临时 PostgreSQL 18 容器中验证 0.2.0 迁移到目标版本、重复运行、旧分组配置保留和新增并发索引有效性。隔离测试不连接两端业务数据库。
7. 管理员点击更新时，从只读发布目录取包、复核 SHA256、备份程序和记录配置，再原子替换持久程序文件。点击重启走 SIGTERM，结束 HTTP 服务并刷完排队记录。

构建或分发失败会在左上角版本弹层显示已发现的官方版本；源码冲突和数据库迁移变化分别显示具体原因。已有验证版本仍可使用。超过 3 小时没有构建检查会显示过期提示。新上游版本发生源码冲突、测试失败或数据库迁移变化时，需要修复适配，系统不会改装不带定制功能的官方包。

自动化边界：检查、无冲突合并、测试、构建和分发自动执行，激活仍由管理员点击“更新 → 重启”。源码冲突或数据库变化需要维护者完成适配，不承诺任意官方版本都能无人维护升级。

### 文件与运行位置

| 位置 | 用途 |
| --- | --- |
| GPU `/data/sub2api-policy-build/policy-log/` | 本目录的源码、补丁及构建脚本副本 |
| GPU `/data/sub2api-policy-build/catalog.json` | 构建状态与已验证版本 |

| 两端 `/opt/sub2api-deploy/data/policy-updates/backups/` | 每次后台更新的配置与目标版本信息 |

运行时程序、已采集请求与发布目录分开存放。Sub2API 入口脚本不会把只读发布目录递归改成应用可写。Compose 固定使用首次接入时已有镜像摘要，并通过持久 command 启动定制程序，所以容器重建也会继续使用定制功能。

首次接入脚本兼容节点系统 Python 3.6；GPU 构建服务固定使用 `/data/miniforge/bin/python3`。首次接入使用 [install_node.py](upgrade/install_node.py)：独立传入目标 SHA256，在无网络、只读根文件系统且 UID 1000 的临时容器中检查版本；备份原 Compose、程序、记录配置和 PostgreSQL dump，并验证 dump 可读取。只重建 `sub2api`，不重建数据库、Redis 或代理。健康检查失败会恢复旧定制程序，并允许从已验证的回退状态重试。

### 维护

```sh
# GPU：查看最近构建状态与日志
systemctl status sub2api-policy-build.timer
journalctl -u sub2api-policy-build.service -n 100 --no-pager

# 手动检查并准备定制新版，不自动激活业务
systemctl start sub2api-policy-build.service
```

修改定制代码时递增 `upgrade/build.py` 的 `REVISION`，同步 `source/`、补丁及 `upstream.json`。同一个已构建版本号不能静默替换成不同源码。用 [sync_bundle.py](upgrade/sync_bundle.py) 和已校验的原始上游归档重新生成完整补丁；在独立完整源码树中验证后再同步 GPU。

GPU 开启 SELinux Enforcing。Miniforge 的 Python 链接及真实解释器原先为 `default_t`，systemd 因无权读取链接而报 `203/EXEC`。接入时仅为 `/data/miniforge/bin/python3(\.13)?` 增加持久 `bin_t` 文件标签规则，并对这两个文件执行 `restorecon`；保持 SELinux Enforcing。重新部署到该路径或升级解释器小版本时需核对标签规则，不关闭 SELinux，也不从错误日志生成宽泛授权策略。

首次发布前和后续自动构建均不发布到公共代码仓库，也不增加公网构建接口。SSH 沿用现有配置，不把凭证写入本目录。
