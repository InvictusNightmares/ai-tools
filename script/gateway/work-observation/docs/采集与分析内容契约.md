# 采集与分析内容契约

2026-09-17 用户确认：目的是让Guard和Auto全面分析用户请求及模型回复，理解大家真实的工作过程。采集并非只为访问统计，也不以DeepSeek占比作为质量证明。

## 原文范围

采集普通文本原文，不脱敏、不做落盘加密。保留消息角色、顺序、工具定义、工具调用参数、工具结果、系统/开发者提示、用户追问、模型可见回复、错误和用量信息。工具文本里的代码、URL、JSON字符串及凭据样式的字面内容均不替换；JSON重新序列化可改变空格/转义形式，但不能改变文本值或数值。原始业务转发字节不受采集处理影响。

Authorization、Cookie、API Key等HTTP鉴权头不采集，不能通过完整header dump间接保存。Key关联使用独立身份标识，不需要存密钥。附件二进制、base64图片/音频和附件下载地址只保留类型、大小、摘要、文件标识等元数据；普通工具正文中的URL不是附件，按原文保留。

上游已经返回的加密压缩状态/签名作为不透明协议字段保留；“取消落盘加密”不意味着能解开上游状态。附件语义、客户端未发送的本地文件、未返回的内部思考不可见，报告须明确缺口。可见音频转录文本保留。

原文只存GPU受限采集/分析工作目录，目录0700、文件0600，30天滚动保留，总上限200GiB。普通日志、统计报告和Git不保存原文。容量不足降级采集，不能静默覆盖未到期记录。外发候选模型仍需具体样本授权。

## 完整工作过程

| 内容 | 保存与分析要求 |
| --- | --- |
| 请求与前文 | 保存网关实际收到的完整请求；原生上下文快照有重复时保留来源，不能只截取最后一句 |
| 响应与流事件 | 保存完整可见回复及有序流事件；delta和最终快照不同，不能重复拼接为多份答案 |
| 工具过程 | 保留定义、调用ID、参数、结果、错误；相同ID仅在可靠身份/会话范围内关联，无法关联明确标记 |
| 追问与纠正 | 按可靠会话关联后保留时间序列；用于发现返工、失败恢复及任务变化，不自动等于质量失败 |
| 取消、超时与丢失 | 保留已观察部分、终止原因、事件ID和缺失范围；不把部分内容伪装成完整会话 |
| 多客户端 | Codex、OpenCode、Hermes、Claude Code分别验证；未知协议、会话归属和子任务关系不得猜测 |

入口区域从服务端监听/路由配置取得，不能相信客户端伪造标签。请求ID由采集端生成；客户端session ID仅为线索，未经验证不能跨用户/区域拼接。重试、压缩、子任务和恢复保留各自事件，不当成新的独立业务任务。

## Guard与Auto如何使用

Guard离线分析用户意图、上下文、工具/引用来源以及模型实际回复，定位正常工作误判和危险反例。本文扩大的是**离线证据范围**，不代表已把生产Guard改成输出拦截，也不把文档/工具结果中的指令当成分析程序的指令。

Auto结合请求难度、协议能力、工具续接、实际输出、后续纠正和完成证据，分析模型是否胜任及不选其他模型的原因。不能从一次选型标签、HTTP200或便宜模型占比推断质量；没有完成证据则质量未知。替代模型工具执行只允许隔离环境。

生产实际记录与离线候选结果分开。候选记录需引用源事件ID、输入版本、策略/模型版本、判断理由、覆盖范围及缺失；不修改生产会话隔离、路由、缓存或重放生产工具。没有实际运行候选的记录不得编造成Guard/Auto判断。
