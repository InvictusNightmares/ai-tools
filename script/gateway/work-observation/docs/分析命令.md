# 本地分析命令（开发阶段）

`tools/analyze.py`不联网，不运行Guard或业务模型，也不执行工具；只有独立SQLite元数据索引。滚动调度由`tools/rolling.py`负责：五分钟tick增量索引采集记录，并在语义worker启用时从有界队列取一批离线任务；每小时另写兼容趋势报告，每天写滚动报告。可选的`tools/semantic.py`只对已校验的完整`http_exchange`事件调用配置的私网Guard预检和Auto`/v1/route`预览，并把结果写入独立`semantic_reviews`表。4000/4001的正式采集已由candidate-r3启用；GPU正式部署的五分钟定时分析使用独立`/etc/work-observation/rolling.json`，不改变正式网关配置。独立无登录复核页由`tools/review_dashboard.py`提供，页面只读取这些结果并把人工标签写到单独库；GPU页面绑定`192.168.64.16:8765`，正式入口与灰度入口固定为 Tokyo `4000 → 4004`、US West `4001 → 4005`，页面不占用任何入口端口。

## 输入与权限

接受管理员从受限采集存储导出的**原始文本正文**`work-observation-v1` JSONL。stdin可使用管道，不要求另存正文临时文件；按用户确认不做正文脱敏或落盘加密。分析库只保留事件ID、关联哈希、客户端、模型、时延、Token、对账费用和缺失标记，不保存请求、响应正文或工具参数。数据库/父目录新建时分别为0600/0700。

```sh
python3 tools/analyze.py --db /受限目录/analysis.sqlite ingest < 采集样本.jsonl
python3 tools/analyze.py --db /受限目录/analysis.sqlite report --hours 1
python3 tools/analyze.py --db /受限目录/analysis.sqlite report --hours 24
python3 tools/analyze.py --db /受限目录/analysis.sqlite report --hours 720
python3 tools/analyze.py --db /受限目录/analysis.sqlite prune
```

导入以区域+采集事件ID幂等，不能拿客户端自报ID代替采集生成ID。后续可用同一事件的已验证USD账单补充费用。实际生产记录才能进入这个索引；`plane=simulation`拒绝导入，模拟必须使用独立数据集及状态。

## 不作过度推断

- HTTP200只表示接口状态；没有经验证的产物测试或人工评审证据，任务质量标记unknown。
- Token只取最新可见usage快照，不累加每个SSE累计快照。缺失usage/账单保留未知，不补零。
- session只能当关联单位，不能自动等同一个完成的任务。未经验证的关联不计算为已验证会话。
- 保留集按区域+身份+已验证根会话哈希固定划分。已识别的子任务须先归一到根会话；关联不确定的记录为unassigned，不进入任何一侧，避免相邻请求泄漏。
- 接入`work-observation`之前，现有4000/4001旧日志没有候选Guard/Auto实际决策；普通统计不能解释这些候选会如何判定。`work-observation`导出的完整可见事件才是离线复核输入，模拟及其理由另存。
- 语义复核结果的`plane`固定为`offline_analysis`，与实际线上事件分开；Guard block或Auto route block是可记录的观察结果，不是对线上请求采取了拦截。端点必须是回环/私网HTTP，公共地址在配置加载时拒绝；任一服务不可用会保留pending而不伪造结论。
- 候选问题列表仅含事件定位信息和失败/缺失原因，不自动改线上策略。
- 时间窗口报告包含事件量、客户端、协议、关联覆盖和未知数量；任务类型语义分布、任务返工成本、全局丢失等尚需后续采集和关联证据。

验证：`python3 -m unittest discover -s tests -v`（当前72项通过、1项跳过；真实监听HTTP测试受本地沙箱限制跳过）。

## 语义复核worker

在`deploy/rolling.example.json`的`semantic`块中默认关闭。隔离验收时可填写同机私网服务，例如：

```json
"semantic": {
  "enabled": true,
  "regions": {
    "tokyo": {
      "guard_url": "http://127.0.0.1:8013/v1/preflight",
      "auto_url": "http://127.0.0.1:8095/v1/route",
      "auto_auth_file": "/run/work-observation/auto-route-tokyo.token",
      "auto_auth_header": "Authorization"
    },
    "us": {
      "guard_url": "http://127.0.0.1:8014/v1/preflight",
      "auto_url": "http://127.0.0.1:8096/v1/route",
      "auto_auth_file": "/run/work-observation/auto-route-us.token",
      "auto_auth_header": "Authorization"
    }
  },
  "timeout_seconds": 3,
  "max_jobs": 20
}
```

每个五分钟滚动tick最多处理`max_jobs`条，Guard读取请求和可见回复但不把正文复制到SQLite；Auto回放只取请求上下文，保留system/developer与最近消息并以`bounded_request_context`限制单条、总上下文、工具schema和envelope大小，结果包括Guard决策/风险/原因和Auto有效模型/分类/路由理由。`ingest_interval_seconds`默认300秒，采集索引和语义消费互不阻塞；单次扫描和语义批次都有上限，积压会在后续tick继续处理。语义队列只接收完整`http_exchange`，WebSocket碎片只留证据。HTTP失败、来源校验失败、队列pending与服务状态分别保留。多区域配置必须使用`regions`映射，事件找不到对应区域时保持pending，绝不回退到另一地区；`auto_auth_file`必须是绝对路径、常规文件且权限为0600，文件只在请求期间读入内存，不能提交到仓库或日志。GPU回环8095/8096的认证隔离回归已完成；分析service模板只放行回环地址并拒绝其它网络，GPU已安装对应timer。

## 健康检查

`tools/health.py --status /受限目录/status.json --state /受限目录/health-state.json --storage-dir /受限目录/data --report /受限目录/health-report.json`只读取采集计数和磁盘余量。状态、健康基线和报告须是三个独立文件，不触碰业务状态。

它区分新增与历史丢失、重启后的计数范围，报告队列压力、磁盘不足、状态陈旧和未知会话关联数量。即使所有检查正常，也不会自动宣称正文全量完整；该结论还需要事件对账。采集关闭时明确不能宣称全量。当前统计/健康检查与证据导出合计19项合成回归通过，GPU五分钟定时调度已部署。

## 完整内容证据导出

统计索引不保存正文。`tools/evidence.py`另行生成包含原始请求/回复的受限JSONL，供离线Guard/Auto分析读取：

```sh
python3 tools/evidence.py --output /受限目录/evidence-唯一批次.jsonl < /受限目录/采集批次.jsonl
```

每条保留完整采集事件、消息来源索引、工具ID、流delta/最终快照标记、关联分组和缺失状态。可靠会话按区域、身份和根会话分组；未知关联保持单事件。正文不脱敏、不加密，文件0600；已有导出拒绝覆盖，失败不发布半份证据。输入按行流式处理，单事件超过64MiB明确失败，不截断后声称完整。

此命令不执行模型、工具或策略修改。`candidate_analysis=null`表示尚未运行候选分析，不能报告为Guard/Auto已完成判断。证据仅描述网关可见部分；附件语义不在首期范围。流式delta和快照可同时存在，不可直接拼接重复答案；工具ID需结合可靠分组和事件顺序才能跨请求关联。导出正文同属30天/200GiB受限存储，管理员须纳入采集存储生命周期，不能放进仓库或公开报告。
