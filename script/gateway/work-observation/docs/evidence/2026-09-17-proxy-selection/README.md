# 独立代理基础性能对照

2026-09-17，GPU隔离回环端口与有CPU/内存限额的容器。未修改生产Nginx、Sub2API、Guard、Auto或客户端入口。源程序见`../../../experiments/`。

## 完成范围

120个测量组合，共37,560次测量请求，全部响应内容校验成功。8种场景、Nginx原路径/Go关闭/Go开启/Rust关闭/Rust开启，三轮轮换顺序。开启采集只做有界复制及后台SHA256，没有正文解析、持久化或四个原生客户端，因此不能当成完整采集验收。

`results.jsonl`为逐次测量及资源数据，`summary.json`为三轮p95的中位数；不是将全部样本混合后重新求p95。`runtime.json`与`binaries.sha256`保存制品/运行范围；`download-checksums.json`对取回文件做SHA256核验。

## 部分结果

以下百分比均为相对原Nginx链路的**额外代理总开销**。采集开/关的增量需要另行对照，不能混成一种指标。

| 场景 | Go 首段p95变化 | Rust 首段p95变化 | Go 总p95变化 | Rust 总p95变化 |
| --- | ---: | ---: | ---: | ---: |
| 约1KiB JSON，无上游等待 | +71.43% | +9.24% | +71.55% | +9.20% |
| 约1KiB JSON，上游20ms | +2.38% | +0.24% | +2.38% | +0.23% |
| 约1MiB JSON，无上游等待 | +2.63% | +9.17% | +2.61% | +9.15% |
| 约1MiB JSON，20ms，50RPS | +0.65% | +0.59% | +0.65% | +0.59% |
| 约1MiB SSE，20ms，50RPS | +0.89% | +0.90% | +0.42% | +0.73% |
| 约4KiB WebSocket，8回合，无等待 | +50.08% | +16.89% | +37.50% | +21.85% |

约1KiB JSON原路径首段p95为0.693ms；Go为1.188ms，Rust为0.757ms。WebSocket原路径八回合总p95为3.749ms；Go为5.155ms，Rust为4.568ms。百分比大并不表示实际多等几秒，但不能据此忽略开销。

固定50RPS长JSON时，包含前置Nginx的峰值RSS：Go约31.04MiB，Rust约47.16MiB；每次交换CPU分别2.83ms和3.28ms（含预热）。Rust在短请求和WebSocket延迟有优势；Go在本次长文本资源开销上较低。不能宣布某语言全面胜出，也未达到完整采集发布条件。

相对同一候选关闭采集的三轮中位数，仍有超过5%的场景：Go短JSON首段+7.12%、8MiB JSON首段/总耗时+5.62%；Rust1MiB JSON约+5.12%/+5.11%、WebSocket约+12.04%/+18.25%。负变化仅代表这批样本差异，不证明采集能加速。完整正文持久化仍须重新验证开/关p95和原链路总开销。

## 完整性及失败证据

- 两个开启候选最终均报告drops=0、queued=0、requests=8,280（含预热）。Go采集字节5,351,970,676，Rust为5,351,970,064，相差612；所有应用层响应相同，但尚未定位帧级差异，不能宣称采集字节完全一致。
- Rust首次构建缺CMake，后在隔离构建镜像补齐；远端实验目录保留构建失败输出。Debian默认镜像下载停滞，构建改用保留APT签名校验的镜像源。
- Pingora0.9.0的`max_retries=0`实际执行零次尝试，冒烟出现EOF；改为1表示只执行首次尝试、不自动重放，随后三协议冒烟通过。
- 初次SSH二进制tar取回被截断，SFTP取回报不存在；改用SSH文本封装、压缩及SHA256校验后完整取回。当前`results.jsonl`为验证过的完整文件，不是截断文件。

实验只使用合成正文。真实请求、附件、密钥和员工原文均未进入本证据目录。
