# 独立采集代理：运行与验收

当前制品为`observation-dev.9`；dev.9增加body-free缺失账本、大块采集缓冲复用、WebSocket完整帧就地解掩码和落盘封装单次写入，已在GPU隔离目录完成gofmt、测试和`CGO_ENABLED=0` Linux构建（见[Go验证证据](evidence/2026-09-17-collector-r1/dev9-go-validation.json)）。当前采集服务使用Go，分析工具使用Python；candidate-r3 已正式接入 GPU 的4000/4001，未修改Sub2API或现有Auto/Guard策略。

30天是正文保留策略，不是上线前必须等待的自然时间；200GiB是统一卷上限，也不是上线前必须写满的容量。两者均通过时间前移、稀疏卷、ENOSPC和到期清理测试验收。真实入口观察可先采用短窗口旁路，watchdog自动监测采集缺失、队列、磁盘和Nginx 5xx，超过阈值立即停止采集并保留业务转发；延迟p95在窗口结束后从事件和访问日志单独复核。

## 构建与隔离运行

在本目录使用Go工具链：

```sh
go test -race ./source/... ./cmd/...
go vet ./source/... ./cmd/...
CGO_ENABLED=0 go build -trimpath -o /受限实验目录/observe ./cmd/observe
/受限实验目录/observe init --dir /受限实验目录/store
/受限实验目录/observe serve --config /受限实验目录/isolated.json
```

从`deploy/isolated.example.json`复制配置到实验目录，设置合成回环上游。开发制品只允许监听loopback；配置默认关闭采集。`identity_salt_file`指向init生成的32字节、0600文件，仅用于稳定关联Key，不是正文加密密钥。鉴权头原样向上游转发，不落入采集记录。

可选`runtime_dir`将开关和状态放到独立受限目录，管理status/enable/disable时`--dir`指向此目录；export仍指向store_dir。sidecar模板只把宿主store挂载到容器`/data/store`，因此模板配置把`store_dir`、`runtime_dir`和`identity_salt_file`统一设为`/data/store`；若改用独立runtime目录，必须同步增加容器挂载和管理命令路径。默认runtime_dir=store_dir。

配置指定可信region/ingress，忽略客户端自报入口。请求侧Bearer与X-API-Key的同一Key使用相同关联值；识别Session-Id、X-Session-Id、X-Claude-Code-Session-Id和既有X-Gateway-Session-Id；Claude子任务ID同样按区域/Key/会话隔离。客户端自报session仅标记client_claimed，不能升级为已验证会话。真实UA保持传递。


GPU语义离线预览是独立的持久服务，不是正式采集入口：

```sh
systemctl enable --now work-observation-semantic-preview@tokyo.service
systemctl enable --now work-observation-semantic-preview@us.service
ss -ltn | grep -E '127\\.0\\.0\\.1:(8095|8096)'
systemctl disable --now work-observation-semantic-preview@tokyo.service work-observation-semantic-preview@us.service
```

服务只读取当前Auto release的绝对二进制和已存在的0600专用认证文件，状态、usage、审计和native文件均写入独立`work-observation-semantic-preview`目录；不读取员工正文、不调用正式8093/8094，不改4000/4001。regional Auto禁止注入共享`AUTO_CLASSIFIER_TOKEN`；持久8095/8096仅在显式route-preview下允许从0600 `AUTO_CLASSIFIER_TOKEN_FILE`读取两地专用 semantic Key，生产regional服务仍只透传调用方凭据。恢复时先检查`systemctl status`、回环监听和`/healthz`，失败就保持停止，不能把route-preview配置到正式入口。

运行时开关通过受限`control.json`传递，最长约1秒生效；重启在开始监听前读取持久化开关，避免启动窗口误采集或漏采集。关闭后既不采集新请求，也不继续复制已存在请求/连接的后续正文；再次开启只开始新的观察，不跨缺口拼接旧会话。先前已经复制的内容可以后台保存，缺口明确标记。转发不因开关重启。

`export`验证每条记录的SHA256后输出JSONL；遇到坏记录报错，不能将中途失败的管道当成完整导出。自动化调用须启用shell的pipefail，或分别检查生产者/消费者退出码。导出包含原文，只能进入受限目录；原文导出及分析副本仍须纳入30天/200GiB整体生命周期，当前开发工具尚未统一管理这些额外副本的额度。

`losses`只输出不含正文的缺失账本（事件ID、UTC时间、原因），用于管理员定位采集缺口；它与原文`export`分开，不能从账本还原请求或回复。

## Docker入口的sidecar接入

GPU上的4000/4001由Docker bridge内的Nginx容器承载，宿主`127.0.0.1`对容器不可达。正式接入使用共享网络命名空间的sidecar：采集器仍绑定回环地址，东京监听`127.0.0.1:18400`、美西监听`127.0.0.1:18401`，Nginx只把内部`proxy_pass`临时切到对应端口，采集器再连接原有`106.14.254.110:9881/9880`。这不会把采集器暴露到宿主公网，也不会把原upstream改成采集器形成环路。

`deploy/work-observation-collector-sidecar@.service`和`deploy/run-collector-sidecar.sh`负责正式sidecar生命周期；`deploy/short_window_cutover.py`只替换一条已核对的`proxy_pass`并保存SHA校验的回退副本；生产 Nginx 的单文件配置是只读 bind mount，因此切换脚本会在 host 原子发布后重启对应容器使新 inode 生效，再执行`nginx -t`。由于 Docker 重启会重建 Nginx 的 network namespace，正式wrapper在切换前、切换后都探测 Nginx→sidecar 路径，切换后必要时重启对应 candidate sidecar 并等待当前 namespace 的18400/18401探针返回200；watchdog运行期间每5秒复核该路径，失联时先关闭采集并恢复原Nginx配置。`short_window_watch.py`只把丢弃、写入、缺失账本、采集不可用、队列或磁盘压力视为完整性故障；单条请求的截断、取消、畸形正文导致的`projection_errors`会保留缺失标记并累计`projection_errors_delta`，不会打掉整条采集链。`--seconds 0`表示无期限运行，它不会重试或重放业务请求。GPU当前由路径独立的candidate-r3 systemd sidecar承接正式4000/4001，东京18400、美西18401；两地无期限watchdog持续运行，短窗口和正式运行的p95仍需从事件与访问日志单独复核。

## 保存和资源边界

- `events/日期/事件ID.json`保存完成的事件，`active/`保存不带正文的请求开始标记。正文不脱敏、不加密；目录0700，文件0600，单写入者锁防止重复进程写同一目录。
- 后台先提取原生附件元数据，再原子发布记录；摘要检测文件损坏。附件二进制不落盘。请求/回复、工具内容和可见原生压缩状态保留原文。
- HTTP/SSE交换结束时保存正文；SSE取消时保留已收到的完整事件，并保留event/id/retry及DONE标记。请求结束前，内存中的正文不保证可抵抗进程强杀；重启会将已登记的未完成请求标为process_interrupted。
- WebSocket按消息后台保存，连接保持打开也可读取。保留独立连接ID、方向和顺序；连接不等于一个任务。解码支持掩码、分片、控制帧和permessage-deflate上下文接续；二进制消息仅元数据。
- HTTP正文摘要对应接收的实体字节；WebSocket消息摘要对应解压后的应用负载。业务转发不重组这些内容。帧解析遵循[RFC7692](https://www.rfc-editor.org/rfc/rfc7692.html)，转发基于[Go ReverseProxy](https://pkg.go.dev/net/http/httputil#ReverseProxy)。
- 默认4096队列项、512MiB正文副本预算、每方向32MiB正文上限。预算覆盖待处理副本和未组装完的WS帧；后台解析/JSON编码、索引及Go运行时有额外内存，512MiB不是进程RSS上限。
- 主记录存储限制200GiB，不覆盖未到期记录；每5分钟尝试按事件时间清理30天前正文。`prune`命令只可在服务停止时使用，运行时由后台worker执行。
- 队列满、正文超限、投影失败或磁盘写失败均有计数和缺失标记。除状态中的最近256条详情外，DiskStore还把事件ID、UTC时间和原因追加到`losses/YYYY-MM-DD.jsonl`，不含正文并随30天清理、200GiB额度计数；写入失败另计`loss_persist_errors`，不阻塞业务转发。

状态每秒更新；做完整性对账必须同时核对本轮请求总数、状态的新旧程度、队列、活动请求及实际记录，不能仅凭队列为零判断完成。WS消息数和连接数不同，不能将written直接与captured作相等比较。

## 退出与恢复

SIGTERM停止接受新连接，给HTTP及WebSocket最多30秒排空；超时关闭剩余套接字，已采集连接标记collector_forced_connection_close。强杀后的恢复不重放用户请求。恢复及到期清理只操作采集目录。

身份文件缺失、存储不可用或启动恢复损坏时，本进程采集保持关闭，业务继续转发；状态记录capture_unavailable及unavailable_bypassed_requests，运行时enable不能绕过故障。修复后需受控重启恢复采集。若状态目录也不可写，只记录不含正文的通用运行错误，由状态陈旧检测报警；这不构成故障记录永久不丢失的保证。

本阶段尚未完成所有导出副本的统一额度/保留管理、原生WS远端压缩状态组合及四客户端真实开发质量验证；性能p95和真实任务质量仍未签收。当前4000/4001采集接入是独立的、可回退的运行态部署，不能把它等同于性能或Guard/Auto训练结论。

## 滚动分析

`python3 tools/rolling.py --config /受限目录/rolling.json`直接读取并校验完成记录，不再复制正文导出。独立SQLite保存统计、源记录引用与待本地复核队列；单次默认最多1000条或20秒，积压下次继续，队列默认最多10000条，其余明确记为deferred。迟到写入的长会话按文件发现，不以请求起始时间作唯一水位而漏读；已有记录幂等去重，坏记录不推进已处理状态。扫描位置同样跨批持久化，避免大量已知文件耗尽预算、使尾部新增文件一直无法导入；目录位置只是提示，完整扫描到末尾后从头复核，因此迟到文件和目录重排不会被永久跳过。

管理员使用`python3 tools/query.py --db /绝对路径/index.sqlite --region tokyo --client codex --limit 50`查询元数据，可按Key、会话、子任务、连接、上游请求ID过滤；不输出正文。请求模型与上游回报模型分列，HTTP请求延迟与WS连接时长分列。

报告v2使用SQL聚合与nearest-rank p95，修复小样本p95被低估的问题；每个分布最多100项，省略部分另列事件数，不能当成完整模型列表。100万条合成记录报告约6.8秒、Python对象峰值24,640字节；SQLite排序使用磁盘，索引/临时文件仍须纳入全局容量管理。

每次执行检查健康；每小时增量、每日近期/30天趋势报告由独立状态控制。`deploy/work-observation-analysis.timer`每5分钟调用，GPU已安装并启用对应service；token-sync timer每10分钟刷新0600离线凭据。网络只允许回环地址并拒绝其它地址，因此启用语义worker时可访问8095/8096而不能访问公共或正式业务网络。运行目录限权，分析索引30天清理，费用/质量无证据仍unknown。Anthropic起始输入和结束输出分别取最后已知用量；WS中间usage不重复当成另一笔总用量。

滚动分析已增加`tools/semantic.py`离线复核worker。开启时，它逐条读取校验后的完整`http_exchange`正文，把请求与可见回复以`plane=offline_analysis`分别送到配置的私网Guard预检和Auto`/v1/route`预览；Guard的allow/block与Auto路由结果都只写入`semantic_reviews`元数据，正文不复制到SQLite，任何生产工具、业务路由、隔离状态和缓存都不执行。Guard/Auto任一不可用会把任务退回pending并计数，来源校验失败则标记failed；因此`complete_local`只表示本地分析结果已记录，不表示原请求当时被线上Guard拦截或实际使用了候选模型。Auto回放只取请求上下文，按`bounded_request_context`限制消息和工具大小并保留截断标记；未知旧协议在离线回放时按完整对话降级为chat，WebSocket碎片保留证据但不进入任务队列。regional Auto若要求认证，可在配置中指定权限为0600的专用`auto_auth_file`和`auto_auth_header`（仅支持`Authorization`/`X-API-Key`）；读取失败时队列保持pending，密钥不落库、不写日志，使用专用认证文件时还会透传事件记录的真实`User-Agent`。持久8095/8096的历史审计显示东京一次复核模型传输错误随后可恢复；候选 Auto 对无HTTP状态的 transport error 增加一次75ms重试，HTTP错误和非法输出仍失败关闭。正式8093/8094明确关闭route-preview，正式配置仍保持关闭；独立分析timer已在GPU启用。72项Python回归覆盖放行、block终态、不可用、陈旧任务恢复、端点限制、认证文件边界、UA透传、旧协议、有界Auto回放和正文不落分析库。分析目录容量预检不是整个200GiB的强制文件系统额度；大规模扫描与分析容量硬限制仍需验收。

正式4000/4001网关本身保持现有Auto/Guard配置；独立分析配置可以把已采集正文按任务送到8095/8096的候选预览，不会改变线上拦截、路由、缓存或业务工具。后续训练应从已采集事件离线生成带版本的候选数据集，经人工标注、验证集评估和灰度后再发布模型或规则。上述worker不是正式采集入口，也不是自动更新模型的持续训练器。

## 全局数据卷（隔离验证中）

`tools/volume.py`管理独立的200GiB稀疏文件卷，只格式化它新建的普通文件，拒绝覆盖既有路径或格式化设备。后续东京、美西、导出、分析及分析临时文件必须放在同一卷内，才能共同受硬上限约束。卷缺失时挂载点权限为000，服务须以专用非root用户运行，并在启动前验证挂载与UUID；这些正式部署约束尚未集成，不能把工具存在说成200GiB全局闭环已完成。

实验只允许在`/data/work-observation-lab`创建256MiB测试卷，演练真实ENOSPC、转发不变、缺失可见、恢复与卸载。不会修改宿主XFS挂载选项或Sub2API数据卷。实际结果见阶段证据。固定容量卷对最终延迟和长期负载的影响仍须加入最终压测。
