# 代理选型实验

此目录仅用合成数据对比转发路径，禁止承接员工或真实模型流量。所有程序只绑定/连接回环地址，不保存正文。

- Pingora固定0.9.0；Go使用标准库ReverseProxy。
- 开启采集的实验仅做有界队列提交和后台SHA256，最多64MiB/4096块。Rust借助引用计数共享块，Go复制块，因为net/http读取缓冲随后会复用。
- 两者都不等待后台消费；队列满计数丢失。必须同时查看丢失，不能拿丢弃日志换吞吐。
- 比较原Nginx→合成上游、Nginx→候选关闭采集→上游、Nginx→候选开启采集→上游。关闭代理重试，避免重复模型请求。
- 测试小JSON、1MiB/8MiB长输入、分段SSE、WebSocket双向数据；测首次正文和总耗时、字节一致、吞吐、CPU和RSS。两候选各两个转发线程，限额2CPU/2GiB，单独后台消费者。

这只能帮助选择转发基础，不包含实际附件处理、持久化、会话关联或四个原生客户端验收，不能用其结果宣称完整采集开销已达标。实际功能完成后仍需重新执行计划中的完整验收。

构建/运行：复制本目录到GPU的`/data/work-observation-lab`，执行`sh build.sh`、`python3 run.py start`、`python3 run.py run --rounds 3`，最后`python3 run.py stop`保存日志并清理**仅本实验的**容器。所有镜像实际ID及编译器版本保存在`runtime.json`。性能记录含每次测量值，保存在`results.jsonl`，已有结果不覆盖。

已发现的实验环境问题：最初负载器使用Debian容器默认CGO编译，直接在GPU旧glibc宿主运行失败（缺GLIBC_2.32/2.34），尚未发送测试请求。已将Go负载器及对照程序改为`CGO_ENABLED=0`；Rust仍在同构容器运行。该失败不计为代理协议错误或性能结果。

首次Rust构建还发现基础镜像缺少Pingora本地依赖需要的CMake；独立构建镜像补齐该工具，原始失败日志保留。没有在宿主或正式容器安装构建依赖。

首次Rust协议冒烟发现`max_retries=0`导致请求EOF：固定版本实际用此字段限制**总尝试次数**（包含首次），不是额外重试数。已按本地0.9.0依赖源码改为1，含义为只尝试一次、不重放；须重跑全部协议测试。最初EOF不能记作通过或计入性能结果。

除固定并发吞吐实验外，另测50RPS固定到达的1MiB JSON/SSE，延迟从计划到达时刻计算，包含压测端排队；不能用闭环压测较低的实际发起速率隐藏排队。
