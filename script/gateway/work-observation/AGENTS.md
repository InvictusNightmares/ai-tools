# 工作过程采集维护约定

- 采集功能单独维护在本目录；既有policy-log职责保持。
- 用户明确要求运行性能优先，不预设Go；选择语言/框架须依据同条件的协议及延迟、CPU、内存和吞吐实测。基础代理实验不能替代完整采集开销验收。
- 业务API兼容、默认关闭、正文30天到期、附件仅元数据、GPU200GiB上限是用户已批准边界。
- 用户已改选GPU独立代理，禁止修改Sub2API源码/镜像/升级流程；原两地2GiB缓冲及跨服务器正文传输取消。先隔离验证，后接入4000/4001；回退不重放已发送请求。
- 日志故障不得影响业务；已丢失/截断/无法关联的数据必须计数，禁止声称完整。
- 用户已取消正文脱敏和落盘加密；原始文本只保存在受限采集目录，鉴权头不采集。普通日志、报告和仓库不保存正文或凭据。
- 目标是完整分析用户请求与模型回复，须保留角色、工具与上下文来源；元数据统计不能替代语义分析。
- HTTP/SSE/WebSocket都要验证；WebSocket具体turn不能仅凭连接ID合并。
- 分析仅在隔离状态执行，不调用生产工具或改变线上Guard隔离、路由和缓存。
- 部署前须验证响应一致、性能p95增幅不超过5%、故障回归及回退；未通过不得开启正式采集。
- 每轮同步本目录CHANGELOG及智能网关总计划，区分开发、验证、已部署和未完成。
