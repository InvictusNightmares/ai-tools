# R02：OpenCode 工具续问中的 Markdown 空值比较误拦截

2026-09-17。最终修复v29/r19已采用到东京4004、美西4005，两地原生OpenCode相同项目的读取与续问均通过。下文按r18首次修复、原生发现第二处失败、r19最终验收分列，旧失败保留。原始请求、工具正文、回答和凭据保留在受限临时目录或服务器审计，仓库只保存结果元数据。

## 根因与旧版复现

东京13:32的请求 `b67be76525b63bb968e40ce0c9c8f3c0` 在两轮工具成功后返回403，原因 `secret_input_not_allowed`。审计中恰有一处被脱敏的内容，对照本机OpenCode工具结果确认是CHANGELOG的Markdown空值比较。r17只接受空白或常见代码标点结束null/undefined/nil/布尔关键字，漏掉反引号，随后把比较运算符的一部分当成凭据值。输入其他位置的正常验证措辞触发了凭据使用硬拦截。

旧版加入4种Markdown比较回归后全部失败；6种字符串、非关键字尾缀、单等号赋值、相邻凭据反例全部保持阻断。不是用户需要改问法，也不是DeepSeek业务模型或分类器作出的拒绝。测试缺口是此前只覆盖普通代码，未覆盖代码在文档中的包装。

## 修复边界与同类路径检查

- 仅在 `guard/redaction.go` 的共享比较识别器中加入反引号结束边界；不跳过整个文档、工具、消息角色或上下文。
- `replaceCredentialAssignments` 只有这一处定义和调用。`redactSecretText` 共享覆盖provider payload、messages、工具名/schema、附件source、metadata值、审计raw body；JSON值与内嵌JSON递归走相同识别器，没有第二份需要同步的比较正则。
- 真正的JSON凭据键、Authorization/Cookie头、已知token、私钥和URL凭据仍执行原规则；不属于本次代码比较边界，保持。完整回归保留这些原有正反例。
- 新回归覆盖单/双/三反引号、中英混合、user/assistant/tool角色、完整provider payload字节不变；字符串比较、null-secret/null.secret、单等号及相邻真实值仍阻断。
- Guard安全规则升至r18，使旧安全决策缓存失效。契约仍为credential-redaction-v1，Auto业务逻辑、分类策略、持久状态schema和业务缓存修订保持。部署重新创建Guard进程，旧进程内误拦会话状态不会遗留。
