## 原因和规则

用户真实 OpenCode“读取改动并总结”会话的五轮主业务均为 Luna low；分类依次 bounded、bounded、multi_step、complex、complex。四个工具续轮已经绑定 Luna，却仍重复 Luna 主分类和 Sol 复核。独立 Sub2API 账单核实主业务 0.0170032 USD、分类 1.2082364 USD（71.06倍）；该口径不含另一个标题请求。真实 UA 已正确透传，不能把此问题归为 UA 或 DeepSeek 不会总结。原始用户请求、工具正文和账单逐行记录不入库。

本次按请求的操作区分 summary/extraction 与实现、审计、诊断。满足低不确定性、无失败、至多一个推理依赖、仅检查可见事实、高置信且全部标签都属于信息整理时，优先 DeepSeek none；材料涉及复杂系统或文件多不提高任务难度。混合审计/开发任务不享受该规则。

| 语义任务 | 最低候选档位 | 默认候选（仍须通过能力、容量、effort和健康检查） |
| --- | ---: | --- |
| simple / 满足全部约束的普通信息整理 | 0 | DeepSeek Flash |
| bounded | 1 | Luna |
| multi_step | 2 | Terra |
| complex | 3 | Sol |
| exceptional | 4 | Astra |

档位是可审查的候选偏好，不是已证明的普遍能力排名或实时价格。独立复核可以纠正高估和低估。新的用户目标超过当前模型下限时立即升级；工具回合仍保留供应商绑定。同目标、同策略、同身份/区域/协议、精确工具调用绑定的纯工具结果复用分类；普通用户补充要求、媒体、旧状态或摘要不匹配均保守重分类。每轮身份、Guard、能力和上下文检查保留，客户端 effort 不参与选择。
