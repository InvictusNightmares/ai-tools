# AI Gateway 维护约定

- 开发前先读 `docs/智能网关与Guard分阶段实施总计划.md`、`docs/维护指南.md` 和相关组件文档，按最新需求及当前未完成阶段执行；需求变化先同步文档，不另起冲突方案。
- 每次代码、配置、部署脚本、测试或上游兼容修改完成，必须在同一轮维护 `docs/CHANGELOG.md` 的 Unreleased，记录原因、变更、兼容/缓存影响、验证结果、部署范围、回滚影响和未完成项；不能留到以后补写。
- 验证失败、未验证和仅本地完成必须如实记录；未更新对应文档和 CHANGELOG，不算本轮开发完成。
- 生产 4000/4001 切换遵守总计划的验收与回退条件。
- 总计划记录当前状态和待办，CHANGELOG 记录历史，README 记录当前用法；历史证据不覆盖，不把旧结果当成新版本通过。
- 代码职责、OpenAI / DeepSeek / Sub2API / Qwen 升级检查及版本失效规则见 `docs/维护指南.md`。
- 唯一 Go module 是 `local/ai-gateway`；Auto 与 Guard 分包、分服务启动，不将业务模型或 vLLM 加载进 Go 进程。
- Go 测试与代码同目录；真实验收工具在 `tools/`，部署在 `deploy/`，文档和脱敏证据在 `docs/`。
- 固定顺序：身份校验 → Guard → 分类/路由 → 业务缓存或上游。Guard 不可用须 fail closed；只做输入保护。
- 客户端 effort 不参与选型；内部目标、实际发送值、上游回报值分开记录。
- 不只改模型名就宣称升级完成；模型、协议、分类、脱敏或缓存语义变化须检查对应版本及回归矩阵。
- 不将 pilot 的固定 Key / Key ID 用于多人入口；复用对应区域 Sub2API 的鉴权、额度和权限。
- 仓库证据不存真实 Key、原始提问、工具正文或思考签名；线上 Guard 脱敏审计正文仍是受限数据。
- 在项目根目录运行 `GO=/path/to/go bash verify.sh`；测试需要本机临时监听，不访问真实模型。
- 本地通过不等于服务器部署、模型质量或客户端验收。不同验证范围分别记录。
