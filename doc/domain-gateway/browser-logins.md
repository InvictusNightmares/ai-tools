# Chrome 本机登录入口迁移

用户确认密码仅保存在本机，选择自行操作修改清单。本次未读取 Chrome 密码库，也未自动修改保存的登录条目或服务端账号密码。

实际旧地址、新网站和完整登录入口保存在工具目录的 `.private/password-manager-migration.json`。该文件权限为 `0600`、由 Git 忽略，仅包含入口映射和操作状态，不包含用户名或密码。公开文档使用以下角色说明。

| 服务 | 需要处理的记录 |
| --- | --- |
| 第一套管理面板 | 对应旧网站下的全部已保存账号 |
| 第二套管理面板 | 对应旧网站下的全部已保存账号，包括目标订阅所属账号 |
| API 管理及受保护扩展 | 对应旧网站，保留原页面路径与查询参数 |
| 任务面板 | 原私网网站条目 |
| 助手后台 | 原私网网站条目 |
| 采集看板 | 如果曾保存则处理；本次未核对是否存在旧条目 |

## 修改步骤

1. 打开 Chrome 设置中的密码管理器。按私有清单中的旧网站搜索，逐条核对服务及账号。
2. 如果网站字段可编辑，将其改为清单的新入口，用户名与密码沿用原保存值。
3. 如果网站字段不可编辑，新增一个新网站条目，填写同一组原账号和密码。先验证新入口能自动填充并登录，再决定是否移除旧条目。
4. 面板使用清单中的完整登录入口，保留原安全路径。其他条目若带路径或查询参数，仅替换协议、主机及端口，不自行删减路径。
5. 私网服务操作前先连接 Tailscale，并使用原获准设备。新增 HTTPS 入口不改变设备允许范围。

Chrome 中修改保存的网站地址，不会修改服务端密码。订阅下载 URL 和节点连接地址也不是密码管理条目；它们的修改及验收记录见[实施记录](implementation.md)。

## 本次交付状态

- 已提供六类服务的本机修改映射；未导出密码。
- 自动打开 Chrome 内置密码页曾被工具的 URL 安全检查拒绝，原因是只允许 HTTP/HTTPS。用户随后明确选择本机手动清单，未改走云端密码管理。
- 修改后的自动填充和实际登录，需要用户完成上述步骤后确认；不能用 HTTPS 可达代替登录验收。
