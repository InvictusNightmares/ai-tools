# 域名迁移遗漏复查

日期：2026-11-17。承接[实施记录](implementation.md)，记录三台主机的后续检查与修复。真实地址、订阅路径、账号、凭据及部署位置只保存在受控私有配置中；本文使用通用角色和占位符。

初次验收偏重 DNS、TLS 和匿名入口，遗漏了登录后的链接、原生订阅来源链和浏览器表单行为。用户指出外部订阅仍使用旧地址后，本次沿实际调用关系检查，而不是只检查页面是否返回成功。

## 发现及处理

| 范围 | 遗漏或故障 | 处理 |
| --- | --- | --- |
| 两套管理面板 | 原生订阅的 `subURI`、`subClashURI` 仍使用旧入口 | 同时更新原始格式和 Clash 格式的规范域名；保留原令牌及路径 |
| 两台公网网关 | 新域名缺少原生订阅转发 | 增加现有原始格式与 Clash 格式的路径；没有启用原本关闭的其他格式 |
| 公网主机 A | 客户端外部订阅仍引用另一台主机的旧地址 | 只替换来源 URL 的 origin，保留安全路径、令牌和客户端关联 |
| 公网主机 B | 原生订阅里的两条节点仍生成旧连接地址 | 为现有入站设置明确的分享地址，改为该主机的域名 |
| 静态订阅 | 生成器 `base_url` 仍从旧入口取源 | 改为新原生订阅入口，执行正常生成任务并与当前发布文件比较 |
| Keeper | `CPA_PUBLIC_URL` 仍指向旧管理入口 | 更新返回链接配置，只重建 Keeper 容器；原插件入口和重定向修复继续保留 |
| 私网登录 | 浏览器表单发送 `Origin: null`，被应用来源校验拒绝 | 将三个私网 vhost 的 `Referrer-Policy` 改为 `same-origin`，保留应用校验 |
| 私网看板 | JSON 未压缩，整批分页又受 15 秒总时限限制 | 网关开启文本压缩；为固定上游版本保存 60 秒总读取时限补丁 |
| 私网助手 | 当前 provider 的 API URL 仍为旧入口 | 修改实际选中 provider 的 `api` 字段，保留模型、协议、密钥和出网配置 |
| Clash 路由 | 逐个列出服务域名冗余 | 在指定的项目规则文件中使用一条 `DOMAIN-SUFFIX`；未部署到客户端或远端规则服务 |

### 订阅链

公网主机 A 的订阅域名同时承载原静态订阅精确路径和现有原生订阅；公网主机 B 的面板域名补充原生订阅路径。应用令牌继续决定能否下载，根目录及无效令牌不会变成公开目录。

依次核对了面板设置、客户端外部订阅表、另一台主机的实际输出、主机 A 的合并输出、静态生成器来源及最终发布文件。最终结果：

- 两套面板的两种订阅 URL 均使用预期新入口。
- 外部来源中目标旧入口已清除，新入口引用数量符合原有配置。
- 另一台主机输出两条节点，只改变两个 `server` 字段；端口、认证、SNI 和协议参数保持原样。
- 主机 A 的两类客户端分别输出两条和七条节点，只有获授权的目标连接地址发生变化。
- 静态订阅仍为七个节点，其中两条使用新域名；下载内容与当前发布文件一致，正常刷新定时器保持启用。
- 原生成器的按节点匹配、预期地址检查及失败回退继续生效。外部来源正常刷新混淆域名不属于本次域名迁移产生的改动。

元数据通过限定记录及原值的事务更新，备份后比较受保护字段。此版本设置读取路径已核对，无需为了展示 URL 字段重启代理进程。不能在运行后直接覆盖整个历史数据库回滚，否则会丢失后来产生的用量或用户变更。

### Keeper

之前已修复插件内嵌入口和重定向泄漏内部端口。本次继续查到应用自己的返回管理页 URL 尚未迁移，更新对应环境配置后，仅重建该扩展容器。

复查包括匿名应用与插件资源返回拒绝、专用入口跳转保持公共 origin、登录后应用返回成功、原同源嵌入保护保持，以及状态接口返回新的管理页 URL。Chrome 中概览与现有数据正常加载。没有修改业务数据、价格或账户。

### 私网表单与看板

短期诊断只记录请求方法、状态和来源类别，捕获到同源表单携带不透明来源。实际应用 `assertSameOrigin` 会拒绝不能解析的 `Origin`；浏览器在原 `no-referrer` 策略下产生 `Origin: null`，所以更换令牌无法解决。

修改为 `same-origin` 后，错误令牌按正常认证逻辑拒绝，原有效令牌可以登录。跨站登录复测返回 403，未登录的数据接口返回 401，登录页面返回同源来源策略和 gzip 响应。诊断配置及临时日志均已移除，未打开跨站访问，也未设置跳过来源检查的环境变量。

看板使用串行分页读取，一轮约七页。压缩前每页约 500 KB；一次测量中前四页单页耗时约 26–41 秒，第五页超时。启用 gzip 后，前六页每页约 120 KB，末页约 60 KB；完整一轮约 21.5 秒。链路状态会影响时间，这不是吞吐保证，但证明原 15 秒整批截止时间不足。页面曾短暂不报错，继续观察后又出现读取失败，因此没有将一次页面加载成功当成轮询已经稳定。

补丁只调整整批读取的截止时间为 60 秒。原 30 秒轮询调度、在途请求互斥、页面离开时取消、登录过期跳转和旧数据保留逻辑不变。JSON 压缩和前端时限解决的是不同条件；不能只增加时间却保留不必要的大响应。

网页补丁已构建并部署，容器健康检查通过，环境变量实际值、数据挂载和监听保持一致。Chrome 重新加载后在前台连续观察 103 秒，列表及来源筛选正常，未再出现自动读取失败提示。该观察覆盖本次验收窗口，不保证所有网络条件下永不超时。旧页面中还观察到过手动刷新结果格式异常的提示；重新加载后该提示未保留，但没有通过主动采集复验，不能记为手动刷新已验证。未为验收触发手动采集、发送通知或修改收藏及已领状态。

### 私网助手

部署端选中的 provider 与仓库基础模板名称不同，本次使用实际配置定位字段。仅替换 `providers.<selected>.api`；没有用模板覆盖用户当前的模型配置。

先从助手的现有出网路径读取新域名的模型列表，确认 HTTPS 与既有密钥可用；再备份、修改并重载专属服务。重载后 Gateway 运行正常，运行解析仍使用新域名。绕过容器原出网代理的预检曾被拒绝，该结果不能代表应用实际访问失败；最终验证沿用现有网络配置，没有调整远端 Clash 路由。

### Clash 通配范围

一条 `DOMAIN-SUFFIX,<ROOT_DOMAIN>,DIRECT` 同时匹配根域名和任意层级子域名，无需逐项列举，也不在此规则中填写 `*`。该规则位于广告规则及兜底规则之前。

本次只修改用户指定的项目规则文件，没有应用到当前 Clash 客户端、静态订阅发布内容或服务器规则服务。之前为私网地址保留的 Fake-IP 过滤继续有效；DIRECT 只决定流量走向，不会为设备授予 Tailscale 访问权限。

公网主机 B 原有的一个代理协议连通问题仍存在，不属于本次网页与订阅 URL 修复。Chrome 本地保存的登录条目由用户按[迁移清单](browser-logins.md)修改，自动填充尚未复验。没有重新验收移动设备、所有写入管理操作、助手聊天或飞书消息。

## 保存、回滚及后续维护

- 参数化网关模板及工具保存在 [工具目录](../../script/domain-gateway/README.md)；看板补丁保存在 [PerkRadar 目录](../../script/qinglong/perkradar/README.md)。
- 本次实际执行的一次性脚本、部署状态和脱敏前的检查结果保存在被 Git 忽略的 `.private/`，目录权限 `0700`、文件 `0600`。不将完整订阅、应用环境、凭据或诊断快照加入 Git。
- 服务端修改前曾创建受控备份，后续已按用户要求删除，详见[清理记录](cleanup.md)。今后恢复前先确认现存材料：订阅元数据按字段及当前值处理，网关恢复对应配置后先检查再重载，Keeper 恢复环境配置后只重建自身。
- 助手回滚只恢复目标 URL 字段，保留后来产生的模型及会话变更，再按需重载该服务。看板原回滚标签和 Compose 备份已删除；仍被其他服务使用的镜像本体及当前源码保留。回滚网页服务不恢复或删除业务数据库。
- SSH 中断后先读取阶段、文件、镜像与实际容器，不把失去输出当成未执行；失败的候选配置不能直接覆盖生产。
- 所有工作区变更尚未提交或推送。后续已清理原回滚备份；旧服务入口和私网访问范围保持不变。
