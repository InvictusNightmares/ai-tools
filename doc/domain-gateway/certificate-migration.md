# 代理、面板与订阅的域名证书迁移

日期：2026-11-17。承接[初次部署](implementation.md)与[遗漏复查](audit-followup.md)。真实地址、账号、端口、部署位置和操作回执保存在受控私有配置中。

后续用户报告公网入口首次访问失败及 API 连接中断。抓包记录到直连路径上的 TLS 握手重置。11 月 18 日复测时直连成功，随后撤回了本地代理规则试验。[访问回归排查](access-regression.md)

## 最终状态

两台公网主机的普通 TLS 代理、面板、原生订阅后端和网页网关均已使用域名证书。旧 IP 证书已从运行配置退出，旧 PEM 文件、ACME 登记目录和专属旧重载任务均已删除。私网主机继续使用已有域名证书，只通过 Tailscale 访问。

迁移按“新旧证书并存 → 验收 → 仅域名证书 → 再次验收 → 删除旧材料”的顺序完成。公网主机 B 使用用户提供的动态验证码完成正常登录和登录后接口验收，两步验证保持开启；验证码不落盘。

## 已实施的变更

| 范围 | 迁移内容 |
| --- | --- |
| 两套面板 | 网页与原生订阅的证书、私钥配置改用域名证书 |
| TLS 代理 | 更新证书校验名；过渡验收后只加载域名证书，继续验证证书 |
| 节点地址 | 五条自有节点统一发布域名地址，保留原认证、协议和连接参数 |
| 主机间转发 | 同时更新内部转发目的地址及 TLS 校验名，保留 REALITY 握手参数 |
| 公网网关 | 原 HTTPS 监听也改用域名证书，保留已有认证、订阅路径及转发规则 |
| 证书安装 | 面板与网关引用同一份正式安装结果，续期通过 ACME 安装机制写入该位置 |
| 静态订阅 | 执行原生成任务重新发布；仍为七个节点，账号、规则、代理组和令牌保持原样 |
| 本机客户端 | 刷新已有订阅，核对生成配置中的域名与 TLS 校验名；未修改路由规则 |
| 私网主机 | 保持原域名证书与 Tailscale 访问范围，仅做只读复核 |

节点的连接域名和证书校验名可以不同。连接域名负责定位服务器，TLS 校验名必须属于证书覆盖范围。REALITY 的握手目标不属于这次普通 TLS 证书迁移，不能一并替换。

外部附加节点的混淆域名会随来源正常刷新。比对时单独记录这些来源字段；不将其混入自有节点迁移，也不放宽账号、端口、规则和其他参数的一致性检查。

## 续期与加载

公网主机 A 的 ACME 客户端仍在原容器内执行，检查调度改由宿主机管理；公网主机 B 继续使用原宿主机 ACME 定时任务。续期与证书重载共同持有一把文件锁，避免安装尚未结束就重启客户端所在容器。

公网主机 A 的镜像启动脚本原本会在每次启动时重新注册容器内 ACME cron。现将该段改为卸载旧 cron 并检查其不存在，完整启动脚本通过只读挂载保留其余逻辑。普通周期任务、fail2ban、镜像、环境变量值、端口和已有挂载保持原样；容器重建和普通重启都已验证不会重新注册。补丁见 [`panel-host-renewal.patch`](../../script/domain-gateway/templates/panel-host-renewal.patch)。

升级面板镜像时，必须从目标版本重新读取完整启动脚本，确认补丁仍适用，并复验重建、重启和续期调度。不能直接用旧版本的完整脚本覆盖新镜像；只删除当前 cron 而不处理启动注册，也会在下次重启时恢复重复任务。

安装成功后只更新 marker，由 path 单元触发加载；另有定时检查补偿遗漏或失败的重载。加载工具按顺序执行：

1. 检查证书有效期、覆盖名称、密钥权限和证书与私钥是否匹配。
2. 等待容器内仍在执行的 ACME 命令结束，并验证 Nginx 配置。
3. 重启面板容器，使网页、原生订阅和代理进程共同加载新证书。
4. 确认面板与代理进程恢复，再重载网页网关。
5. 仅在全部成功且证书文件没有再次变化后记录已加载摘要。摘要未变时定时检查不会重复重启。

通用代码见 [`reload_services.py`](../../script/domain-gateway/reload_services.py)，参数结构见 [`reload.example.json`](../../script/domain-gateway/reload.example.json)。实际服务单元、安装位置和调度参数保存在私有操作记录中。

续期单元执行原 ACME 命令时必须使用与重载配置相同的锁：

```text
/usr/bin/flock <SHARED_RENEWAL_LOCK> <EXISTING_ACME_COMMAND_AND_ARGUMENTS>
```

本次使用已经签发的正式域名证书，没有为了验收强制重新签发。私网 DNS 验证令牌和验证别名保持原用途。

## 验收与已知边界

- 两台后端实际呈现的证书已与安装结果比对，验证信任链和域名；同时检查数据库与代理运行配置一致。
- 旧证书退出运行后，五条自有代理连续三轮通过隔离客户端的完整 HTTPS 请求，包含主机间转发。删除旧材料后及最后一次启动修复后，各重新验证五条代理并全部通过。
- 当前 Clash 核心的五条节点和经现有节点访问两套面板的 HTTPS 检查均通过。迁移过程中仍观察到既有链路的间歇超时，不能将这些通过结果解释为长期网络稳定性保证。
- 原始格式与 Clash 格式订阅均使用新地址和校验名。静态七节点发布内容与当前文件一致，受保护字段保持原样。
- 公网主机 A 在网页证书切换并重载后，已在 Chrome 中读取登录后的系统状态。之后仅代理证书数组和调度启动方式变化，网页证书及认证设置未变；新的 TLS、页面和订阅检查通过。后续浏览器直连重试出现连接重置，没有计为新的登录成功。
- 公网主机 B 通过原账号、密码和动态验证码完成正常登录，并在旧证书删除后再次读取已认证的入站列表接口。未重置密码、关闭两步验证或读取验证种子。
- 两台新的证书加载工具都已实际执行；第二次未变更检查正确跳过。删除旧材料后的普通 ACME 续期检查、marker → path 单元触发、未变更摘要检查均通过；每台仅保留一项域名续期登记，无 IP 续期登记。尚未发生到期后的真实自动续期，不能将检查和演练称为已完成一个续期周期。
- 私网三个服务的可信 HTTPS 与预期状态码通过，网关仍只绑定 Tailscale 地址。
- 本机公网直连出现过连接关闭或重置，SSH 与 HTTPS 都受影响；重启客户端后一度恢复，之后直连重试仍有波动，尚不足以确认唯一原因。没有关闭证书验证或修改路由来掩盖问题。

本轮自动测试：域名工具十九项通过，一项需要显式指定原生 Nginx 镜像的既有测试跳过；订阅生成器四十五项通过。两台实际 Nginx 配置检查通过。新增测试覆盖重载部分失败、证书安装过程中变化、ACME 未退出、Docker 进程查询要求和 OpenSSL 名称检查的返回状态差异。

## 旧证书清理

本轮登录与业务验收通过后，已完成以下操作：

1. 从代理运行配置移除旧证书，继续保留旧文件供必要回退；复验新证书独立工作。
2. 确认数据库、运行配置、网关、续期回调和服务单元都不再依赖旧证书。
3. 用 ACME 的移除命令取消指定旧 IP 的续期登记，再删除该登记目录、已确认的旧 PEM 文件和专属旧重载任务。
4. 保留域名共用调度、ACME 账号、验证 webroot、静态订阅和业务数据。旧目录名可能仍承载这些活跃数据，不能整目录清空。
5. 再次验证面板、订阅、代理和正常续期检查，随后清理本轮临时回退材料及测试登录 Cookie。

删除工具先生成精确目标清单，拒绝符号链接及目标漂移；中断后仅继续处理清单中尚未完成的项目。过渡期间的回滚按字段和原值核对，不恢复整份历史数据库，以免覆盖之后发生的流量统计或用户操作。旧证书删除后，不能再依赖原 IP 证书恢复旧 IP HTTPS 入口。

两台公网主机的本次临时回退目录均已删除。公网主机 B 的废弃域名证书副本经确认未被容器挂载、未被当前 Compose 引用，且与正式安装结果一致后删除；现用证书保留。本机包含节点凭据的临时候选配置也已清理。

一次性迁移、验证、清理脚本和回执保存在工具目录下被 Git 忽略的 `.private/certificate-migration/`，目录权限 `0700`，文件 `0600`。迁移脚本供追溯本轮操作，不应在回退材料已删除后直接重跑。本轮没有修改根目录 `AGENTS.md`，没有提交或推送。
