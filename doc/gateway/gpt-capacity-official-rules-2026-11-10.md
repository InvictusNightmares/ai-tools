# GPT 扩容测算：官方额度与报价口径

核实日期：2026-11-10。以下为当日读取的公开官方文档，价格、产品组合及限制可能调整；不包含内部部署信息，也未验证任何具体账号的实时权益。

## OpenAI：订阅容量不能按 API 美元反推

- Plus 为 20 美元/月；Pro 提供 100、200、500 美元/月档位；Business 年付为 20 美元/人/月，月付为 25 美元/人/月，2 人起。当前文档将 Plus、Standard Business 的用量估算放在 5 小时窗口内，明确当前 Pro 没有 5 小时限制；周限制仍可能适用。实际窗口、额度和重置时间以账号用量页面为准。
- 模型、上下文、推理、工具、缓存以及速度模式都会改变额度消耗；文档没有给出可通用于所有工作负载的“每个 Pro 每周固定 token 数”。API token 价格与订阅内用量分开，不能用 API 价格或内部美元记账反推订阅容量。
- 到限额后可购买 credits，或者用 API Key 按 API 价格继续使用。

以上来源：[OpenAI Pricing](https://learn.chatgpt.com/docs/pricing)。

### Pro 100 与 Pro 200 的倍率核对

当前官方帮助页（抓取时标注七天前更新）说明：Pro 100、Pro 500 的 Work/Codex 额度已较此前翻倍；Pro 200 取消此前宣布的额度削减，原高额度保留、原低额度翻倍，两类及新订阅现已统一。页面只明确 Pro 200 用量高于 Pro 100，未给出当前精确倍数；额度翻倍也不保证任务完成数翻倍。

因此不能根据月费把 Pro 100 当作 0.5 个 Pro 200。搜索缓存仍可见旧版 5x/20x 表，但重新读取当前英文、中文正文后，该表已被替换，不能将旧摘要作为现行倍率证明。近期测量窗口可能跨越权益调整，需按账号套餐和事件时间分段。来源：[About ChatGPT Pro tiers](https://help.openai.com/en/articles/9793128-about-chatgpt-pro-tiers)。

## “重置”须分清三个层次

| 层次 | 能确认的含义 | 扩容测算处理 |
| --- | --- | --- |
| 上游正常周期恢复 | 官方限额数据提供已用百分比、窗口时长和下次重置时间 | 属于正常供给；保留 |
| 上游额外重置 | 官方另有 earned reset credits，包含可用数量、授予时间与可选到期时间；兑换可能因无券或无合格窗口而失败 | 稳定容量基线设为零，不承诺长期可重复获得 |
| 内部网关额度清零 | 是否存在、清零对象和时间须由本地审计证据确认 | 内部清零不能证明上游供给增加；其放行的实际请求仍应计入需求 |

前两行依据：[OpenAI App Server：Rate limits 与 Earned rate-limit resets](https://learn.chatgpt.com/docs/app-server#8-earned-rate-limit-resets-chatgpt)。第三行为系统边界分析，不是对现网行为的事实判断。官方资料不能证明某次现场“重置”属于哪一类。

上游周额度提前恢复也不等于用户兑换了重置券；产品发布、统一额度调整等事件同样需要按实际记录识别。用于“不再提前恢复”的测算时，保留正常周恢复，排除额外恢复带来的补充量。

## 用于现网测算的建议方法

以下为分析方法，不是官方容量承诺：

1. 统计最近完整周的 GPT 成功用量，并另外记录因限额失败、排队或降级的需求；将模型、缓存和输出拆开。今天尚未结束的用量不直接与整天相比。
2. 用未发生额外重置的同套餐账号完整周期估算单号容量；若只有重置期间数据，需按每次重置前后额度变化还原消耗，不能直接采用当前剩余百分比。
3. 总量口径可写为 `目标账号数 = ceil(设计周需求 / 单号正常周有效容量 × 余量系数)`。另核对短时并发与各资源组独立用量，取更高需求；不能只按总体平均分配。
4. 单号容量尚未获得可靠实测时，应给条件区间与补采数据要求。20%～30% 余量可作为初始规划假设，不能包装成统计结论。额外重置次数也不能直接按整数倍扩容：只有每次都接近耗尽且完整恢复、工作负载稳定等条件成立时，才可粗略按额外提供的完整额度折算。
5. 将用户人数、GPT 真实需求、单号可交付容量、内部记账额度和实际采购现金分别列出；保留现有 DeepSeek 用量，不能无证据假设它能替代全部 GPT 工作。
